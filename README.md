# Детекция мошеннических транзакций с использованием машинного обучения

## Описание

Проект направлен на прогнозирование вероятности мошенничества по транзакционным и идентификационным данным (датасет IEEE-CIS Fraud Detection). Решение включает полный цикл:

- Анализ и предобработка данных (394 признака транзакций + 41 признак идентификации устройства)
- Визуализация распределений признаков и их связи с таргетом
- Feature engineering категориальных признаков (группировка признаков, обработка пропусков)
- Обучение моделей (CatBoost, Random Forest)
- Оценка метрик (Precision/Recall/F1, PR-AUC, ROC-AUC)
- Интерпретация модели с помощью SHAP и Feature Importance

## Ключевые особенности

✅ Объединение транзакционных и идентификационных таблиц (`left join` с сохранением полного объёма данных)
✅ Обработка сильно разреженных признаков (до 96% пропусков в отдельных колонках)
✅ Группировка категориальных признаков высокой кардинальности (ОС, браузеры) через regex
✅ Работа с сильным дисбалансом классов (~3.5% fraud) через `class_weights`
✅ Сравнение native-обработки категорий (CatBoost) и One-Hot Encoding (Random Forest)
✅ Интерпретация решений модели через SHAP на уровне отдельных признаков и объектов

## Технологии

- Python 3.x
- Библиотеки: Pandas, NumPy, Seaborn, Matplotlib, Scikit-learn, CatBoost, SHAP

## Основные признаки

Датасет содержит 432 признака после объединения таблиц; из-за объёма перечислены по группам:

- **TransactionAmt, TransactionDT** — сумма и время транзакции
- **card1–card6** — характеристики карты (тип, банк-эмитент, категория)
- **addr1, addr2, dist1, dist2** — адресные признаки и дистанции
- **P_emaildomain, R_emaildomain** — почтовые домены покупателя/получателя
- **C1–C14** — анонимизированные счётчики (частоты, связанные с картой/адресом)
- **D1–D15** — временные дельты между транзакциями
- **M1–M9** — бинарные флаги соответствия (match) данных
- **V1–V339** — анонимизированные инженерные признаки от Vesta
- **id_01–id_38, DeviceType** — идентификационные признаки устройства и сессии
- **os_group, browser_group** — сконструированные признаки (группировка ОС/браузера по семействам)

## Результаты

Я сравнил две модели — **CatBoost** и **Random Forest** — и остановился на **CatBoost** как на основной модели. Она даёт заметно более сбалансированный компромисс между полнотой и точностью, что критично для fraud-детекции, где пропущенное мошенничество обычно дороже ложного срабатывания.

**Метрики модели (CatBoost, класс fraud):**

| Метрика | CatBoost | Random Forest |
|---|---|---|
| Precision | 0.72 | 0.91 |
| Recall | 0.76 | 0.53 |
| F1-score | 0.74 | 0.66 |
| Accuracy (общая) | 0.98 | 0.98 |

Random Forest даёт значительно более высокую точность (меньше ложных тревог), но пропускает почти половину реального мошенничества (recall 0.53) — для этой задачи такой компромисс менее предпочтителен, чем у CatBoost.

**Интерпретируемость влияния ключевых факторов** (по SHAP и feature importance) соответствует доменной логике: сумма транзакции, характеристики карты (card1, card2, card6) и анонимизированные счётчики (C13, C1, C14) оказались среди самых влиятельных признаков наряду с фактом отсутствия идентификационных данных устройства.

### Ограничения модели

- Признаки **V1–V339** анонимизированы Vesta без описания — интерпретация возможна только через статистику важности, без привязки к бизнес-смыслу
- Часть identity-признаков (`id_07`, `id_08`, `id_21`–`id_27`) заполнена менее чем на 4% — сигнал от них, вероятно, минимален
- Обучение велось на первых 500 000 строк исходного файла (хронологически ранний период), а не на полном датасете — модель может хуже обобщаться на более поздние транзакции
- Валидация сделана через `train_test_split` со случайным перемешиванием, а не строго по времени — при транзакционных данных это может давать чуть завышенную оценку качества по сравнению с реальным сценарием "предсказываем будущее по прошлому"
- `TransactionID` не был исключён из признаков и попал в топ важности по SHAP — похоже на артефакт (корреляция с порядком/временем транзакций), а не на реальный экономический сигнал

### Улучшения

- Перейти на полноценное хронологическое разделение train/val по `TransactionDT` для более честной оценки
- Исключить `TransactionID` из признаков и переобучить модель
- Добавить агрегированные признаки (частота транзакций и средний чек по `card1`/`addr1`)
- Подобрать гиперпараметры через Optuna вместо ручного перебора `iterations`
- Сравнить `class_weights` с SMOTE/undersampling на кросс-валидации
- Дособрать/уточнить сильно разреженные identity-признаки или обоснованно исключить их

### Примеры

- Если у транзакции отсутствуют идентификационные данные устройства (`id_33` не заполнен), вероятность fraud по модели заметно выше — 10.8% против 4.5% при наличии данных
- Транзакции с мобильных устройств (`DeviceType = mobile`) имеют более высокий fraud rate (9.85%), чем с десктопа (6.35%)
- Рост анонимизированного признака `C13` сдвигает предсказание модели в сторону fraud
- Высокие значения `card2`, напротив, снижают предсказанную моделью вероятность мошенничества
